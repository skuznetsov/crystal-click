# Fixed Numeric Wide-Part Scan Frontier

Document status: implemented and VERIFIED within the bounded public-fixture
scope below; no general ClickHouse type compatibility claim.

Current frontier: a typed, callback-scoped scan for exact primitive numeric
columns in immutable local Wide MergeTree parts. Preserve the existing
`UInt64` APIs and the offline catalog's candidate/overlap rules.

## Factual anchor

At pinned ClickHouse source `066ea77c`, `SerializationNumber<T>::serializeBinaryBulk`
writes contiguous `sizeof(T)` values in little-endian order. The current
`WidePart` reader already validates one selected physical stream, compressed
frames, marks, selected checksum-entry sizes, and row counts, but hard-codes
eight-byte values. `ChecksumVerification::SizeChecked` does not mean that
ClickHouse's compressed-frame or part-file hashes are verified.

## Admitted surface

- Exact `UInt8`, `UInt16`, `UInt32`, `UInt64`, `Int8`, `Int16`, `Int32`,
  `Int64`, `Float32`, and `Float64` in `columns.txt` and table DDL.
- One physical data stream per selected column, with the currently supported
  Wide marks and compression codecs. Decode little-endian bytes to the exact
  Crystal type, including signed boundaries and floating-point bit patterns.
- A mixed-type table scan yields row-aligned borrowed typed slices. The caller
  specifies the expected Crystal type when retrieving a column; a mismatch
  raises before values are used. Preserve part/mark/source offsets and the
  existing `scan_uint64` and `values_for(column)` contract unchanged.
- Offline table selection remains exact `MergeTree` and immutable single-disk
  physical candidates. Reject overlapping candidates before any callback.

Crystal caller example:

```crystal
table = CrystalClick::OfflineCatalog.open("/path/to/clickhouse-root").table("lab", "events")
table.scan_numeric(["id", "cost"], batch_rows: 256) do |batch|
  ids = batch.values_for("id", UInt32)
  costs = batch.values_for("cost", Float64)
  ids.each_with_index do |id, index|
    puts "#{id}: #{costs[index]}" if id > 100_u32
  end
end
```

The example requires an exact `UInt32` `id` and exact `Float64` `cost` in
both table DDL and each selected part; it is illustrative, not a bundled
fixture schema.

## Rejected surface

- `String`, `FixedString`, `Nullable`, `LowCardinality`, arrays, tuples, maps,
  decimals, enums, UUID, Date/DateTime aliases, 128/256-bit integers, and
  implicit casts. DDL inspection remains available for unsupported types.
- Compact parts, live `system.*` state, concurrent mutation guarantees, and
  automatic active-part selection.
- New Delta widths or codec chains beyond the reader's existing support.

## Design laws and falsifiers

Risk tier: CAUTION, because wrong width, sign, or row alignment could silently
return incorrect values. Rollback: one feature commit. DoD: focused numeric
specs plus full debug and release suites, formatter and diff checks. A public
ClickHouse-produced mixed-type fixture must agree with known row values.

1. The selected type in the part and table DDL must agree exactly; a typed
   accessor cannot reinterpret another type with the same width.
2. Validate mark offsets and expected decompressed byte counts using selected
   element width, with checked arithmetic. Reject truncation, trailing bytes,
   misalignment, and row-count divergence before yielding the affected batch.
3. Keep all selected columns aligned to the same part and mark rows. Do not
   silently skip a malformed later column or part.
4. Preserve the callback lifetime rule; returned slices cannot be retained as
   independent owning data.
5. Preflight schema, marks, and selected file metadata before scanning, and
   materialize every selected column of a mark before yielding that mark's
   first batch. A corrupt later data frame can still fail after earlier marks
   have yielded callbacks; the scan is not transactional.

Falsifiers: mixed primitive widths and signed/float boundaries; table vs part
type mismatch; typed accessor mismatch; truncated/misaligned numeric stream;
corrupt later column; overlapping parts with zero callbacks; existing UInt64
regression fixtures. The strongest expected failure is a same-width type being
reinterpreted without a declared-type check.

Evidence decays if ClickHouse numeric serialization, mark layout, fixture
producer, or the shared reader changes. Refresh against the pinned source and
the generated public fixture before widening support.

## Implementation seal

The public fixture generated by `scripts/generate_fixed_numeric_fixture.sh`
uses ClickHouse local `26.7.1.1315` and has ten one-stream primitive columns,
four rows, two marks per column, LZ4 data, and plain `.mrk2` marks. Its known
integer extrema and exact float bit patterns (including negative zero) agree
with the Crystal reader. The focused numeric spec passes 10/10, and the full
debug and release suites pass 177/177 each. Crystal formatting, shell syntax,
fixture shape, and Git whitespace checks pass. The independent adversary pass
also checked ordered values and provenance across two non-overlapping parts,
type disagreement of equal-width columns, mark-byte mismatch, and zero
callbacks for a corrupted later selected column in the same mark. Verdict:
ROBUST for this declared primitive Wide-part slice.

The fixture does not exercise NaN payloads or every codec/mark combination for
each new type. Data corruption in a later mark may be discovered after earlier
callbacks. `String`, nullable and composite serializations remain rejected.
