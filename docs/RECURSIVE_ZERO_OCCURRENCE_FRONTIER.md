# Recursive whole-part zero-occurrence qualification — W205

Document status: finite qualification VERIFIED; scoped adversary verdict ROBUST.
Baseline: `7b7c411a5635119f5e4d1b50ee42dae86c3c19fd`.

## Boundary

W204 already implements recursive Array/Tuple composition of JSON Object sites
and JSON-free Dynamic sites. Its library tests cover a whole part with parent
rows P > 0 and child occurrences Q = 0. Its stock interoperability corpus only
has zero-Q marks/windows inside otherwise nonempty child sites. This slice
qualifies the missing whole-part case; it does not widen type admission.

Admitted after the gates below: the existing public complete-part writer,
recursive column reader, and typed table callback retain parent rows when every
Array element site is empty, under both qualified String profiles.

Rejected/unchanged: JSON as a Dynamic actual or Variant arm, new declared
wrapper kinds, Compact/flattened/legacy layouts, unqualified dictionaries,
general catalog publication, full MV/projections, and performance claims.
The overall goal remains active, with performance deferred until type and
MV/projection coverage is complete.

## Design laws

1. Physical marks, structure metadata, statistics and terminal EOF follow P.
   Value lanes and Object/Dynamic occurrences follow Q, including Q = 0 for
   every mark. Empty values do not permit dropping descriptor validation.
2. An explicit writer roster need not equal the stock writer's chosen empty
   roster. Each part is checked against its own exact persisted descriptor and
   physical stream roster. Stock must read the library's unused declared arms;
   the library must read the stock's independently chosen empty roster.
3. Reuse W204 production owners unchanged unless a behavioral falsifier exposes
   an actual defect. Do not manufacture a stock witness by rewriting its data.
4. Negative preflight must neither publish a part/stage nor invoke a table
   callback. Empty selected windows are not substitutes for whole-site Q = 0.
5. Native oracles are independently authored literals and exact stream lists;
   helper self-reports and CHECK success alone are insufficient certificates.

## DoD and falsifiers

- The exact affected roster, including focused W204/W205 specs and relevant
  owner specs, passes DEBUG and RELEASE without failures, errors or pending
  examples. A separate focused DEBUG gate also passes; no separately executed
  focused RELEASE gate is claimed.
- Fresh DEBUG and RELEASE helpers at the tested source each pass both native
  directions for both String profiles. Persisted parent counts/keys survive,
  all child arrays are empty, and declarations/streams are checked exactly.
- Stock source and directly attached library files remain unchanged across
  reads. Helper reports and generated bytes agree across build modes.
- A seeded wrong parent/child count, dropped structure stream or wrong literal
  must be rejected. Check unused actual depth and no-callback/no-publication
  behavior despite zero data occurrences.
- Strongest likely failure: two library owners agree on deleting state or
  using Q as the physical grid, while the stock writer/reader does not. Native
  parts and independently authored value/stream observations distinguish it.

## Observed result

No production changes were required. The same exact 182 affected files pass
1125 DEBUG and 1125 RELEASE examples; focused DEBUG passes 22. All successful
gates have zero failures/errors/pending and guarded actual exits 0.

Fresh helpers in both modes qualify the stated whole-part carrier under both
String profiles, in both native directions. Per mode: two direct library
ATTACHes, six CHECKs, 96 independent selected-row observations over repeated
windows and 122 unchanged published files. All 62 generated library files and
normalized reports agree across modes. Stock chooses an empty actual/path
roster; the library prepares an unused UInt64 arm. Neither roster is rewritten
to make it match the other.

The unused LowCardinality(String) actual positive case is library-only. Its
negative test mutates a persisted Array size from 0 to 1, keeps the P grid and
reseals checksums. Explicit physical-size/file-hash checks and a reopened raw
stream/grid check pass. Dynamic LC occurrence census then rejects the invented
child before any table callback. The first test prediction named a later guard;
root corrected only the expected message after observing the earlier rejection.

Root independently authenticated raw captures, exact physical stream rosters,
literal parent keys/empty arrays, active ATTACH paths and cross-mode bytes.
Nine seeded oracle/instrument mutations reject per mode; these are distinct
from the persisted semantic contradiction above. Candidate model reviews are
correlated, not independent execution evidence. The evidence index is
`.landmark/evidence/recursive-zero-occurrence-w205.json`; its scope does not
admit additional types/layouts or complete the overall goal.

## Next capability

After this validation gate, bind an ordinary explicit Dynamic JSON actual to
the existing Object physical owner. That requires a generic external leaf
handoff in the recursive bulk traversal, not a serializer per wrapper/leaf
product. SharedVariant's inline JSON envelope is a distinct unqualified lane;
it must not be admitted by deleting ordinary-arm guards indiscriminately.

Descriptor representability and value-ready storage admission are separate
boundaries. A future direct-JSON actual should reuse Dynamic's existing roster,
statistics and canonical-index owner; its physical/value plan must require an
exact Object binding. Bare value APIs, Object-typed Dynamic and SharedVariant
must retain explicit guards until their own contracts are qualified. No second
roster parser or blanket `contains_json?` admission is proposed here.

The helper's `library_prepared_actual_roster` is the writer input, not a
read-back metadata witness. Exact independently authored physical stream names,
the persisted substream manifest and stock reads provide the roster evidence.
